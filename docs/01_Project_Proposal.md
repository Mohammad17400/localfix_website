# LocalFix project proposal

**Status:** Draft for instructor/team review. Frontend-only scope.

## Problem hypothesis

Customers may find it difficult to compare local service providers because service information is scattered across personal contacts and social media. Providers may also struggle to organize incoming requests. These claims are assumptions to validate through interviews; no research results are claimed.

## Proposed solution

A responsive local services marketplace for Kabul. Customers browse services, inspect provider profiles and submit requests. Providers manage service listings and request status. Administrators manage category and provider visibility. A role/account switcher demonstrates each perspective in one browser.

## Objectives

1. Make service discovery possible by category, neighborhood and search term.
2. Support a complete request-to-completion workflow with clear status feedback.
3. Preserve demonstration data after refresh using localStorage.
4. Demonstrate software analysis, conceptual modeling, design, JavaScript/React development and testing.
5. Produce understandable code and documentation suitable for a course presentation.

## Target users / stakeholders

Customers, local service providers, marketplace administrators, the student team and course instructor.

## Included scope

Kabul; four initial categories; about 12 fictional providers; service discovery; profiles; request form; customer/provider/admin views; reviews; favorites; service/category management; browser persistence; responsive design and motion.

## Excluded scope

Backend and database server, real authentication, real payments, email/SMS, GPS, live chat, identity verification, real bookings and cross-device synchronization. This scope must be disclosed to the instructor. The conceptual ERD represents arrays, not a deployed database.

## Expected benefits

A consistent place to inspect service information; clearer request details; visible status changes; and a realistic educational demonstration of a marketplace workflow. Actual user value requires validation.
